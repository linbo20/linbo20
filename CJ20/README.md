# CJ20：UWB 连续波形、体动及生理参数离线分析

## 使用

建议 Python 3.10 或以上。在项目目录执行：

```bash
python -m pip install -r requirements.txt
python main.py
```

日常使用只修改 `main.py` 中的 `INPUT_FOLDER`，填入**直接存放 BIN 文件的目录**。该目录自身或任一父目录必须名为 `radar_2026-11-05-19-36-34` 这种格式。输出自动写到输入目录下 `vitals_output/`。不需要单独配置输出路径。Windows 路径保留 `r"..."` 写法。

默认硬件协议与用户给出的解析一致：100 Hz、8 RX、32 taps（物理索引 65–96）、little-endian int16、Q 在前 I 在后、无帧头，每个文件 100 帧。**帧字节数正确不能证明协议正确**；若设备有帧头或通道顺序不同，必须先核对厂商协议。最后文件允许不足 100 帧，其余文件不足帧、空文件、文件缺号、重复编号、多 COM 混流会报错，不静默拼接。

## 处理思路

1. 按文件数字编号排序，解析为 `(frames, 8, 32)` 复数 CIR。
2. 对全部 RX/tap 计算相邻帧复数变化量，按能量归一化，再取 RX 中位数，得到每帧体动分数。0.2 秒平滑，使用固定下限与 MAD 自适应阈值；变化超过固定下限三倍也判体动。分数无量纲，不是物理速度或加速度。
3. 全程选择一个幅度足够、相对复数变化较强的 RX/tap，并固定使用，避免窗口间切换通道造成相位跳变。此为单人、距离基本固定的基线实现，未做目标跟踪、多通道波束合成或 IQ 圆拟合。
4. 体动前后各扩展 3 秒，独立处理每个无体动片段。相位展开、线性去趋势，四阶 Butterworth SOS 双向零相位滤波：呼吸 0.1–0.6 Hz（6–36 次/分），心脏候选成分 0.8–2.5 Hz（48–150 次/分）。每段两端额外舍弃 5 秒降低滤波边界影响；短于 15 秒的干净片段不输出有效波形。3 秒和 5 秒是工程默认值，不保证完全消除所有长瞬态。
5. **连续波形只生成一次，不逐窗拼接**。30 秒窗口、1 秒步长估计速率；结尾追加一个与最后帧对齐的完整窗口。任一无效样本使该窗口速率无效，不跨体动段拼接频谱。少于 30 秒的数据仍保留每帧结果，但不输出速率记录。
6. Hann 窗周期图峰值加局部插值估计频率，峰附近三个频点占频带内功率的比例作为谱集中度，低于 0.35 判无效。30 秒真实频率分辨率约 2 次/分，插值不增加真实分辨能力。若心率落在呼吸频率 2–8 倍附近（±3 次/分），保守标记为呼吸谐波歧义，并将心率置 NaN。
7. 在有效心率窗口覆盖的连续干净片段中检测心脏候选波形峰值，输出相邻峰间期；不跨片段计算间期，不补造丢失心搏。

波形是带限相位代理信号，单位 rad；未用载频转换为毫米。心脏候选波形不是 ECG；滤波无法单独保证心脏来源。体动阈值、距离单元选择、呼吸谐波判断都需要根据真实数据评估。默认固定 tap 可能选到杂波或非胸部目标；目前没有“检测到人体”的独立证明，静态环境中的周期干扰也可能通过质量检查。需要更改算法参数时集中修改 `uwb_vitals/config.py`，普通采集处理只需改输入目录。

## 导出数据

| 文件 | 内容 |
| --- | --- |
| `frames.csv` | 每帧一行，绝不删除帧，包含帧号、相对秒、带时区时间、体动分数、原始体动标记、扩展污染标记、波形有效标记、去趋势相位、呼吸/心脏候选波形 |
| `waveforms.npz` | 同步的逐帧 NumPy 数组，保留布尔类型和 NaN；起始绝对时间见 metadata |
| `rates_30s.csv` | 30 秒窗口起止帧、中心秒/时间、有效比例、体动比例、呼吸率/心率、谱集中度、有效标记、谐波歧义标记 |
| `candidate_ibi.csv` | 候选峰前后帧号、后峰时间、片段 ID、IBI 毫秒、生理范围合理标记；`validated_for_hrv` 始终 False |
| `metadata.json` | 参数、选中 RX/tap、体动阈值、时间假设、文件帧映射、时长及限制 |
| `overview.png` | 整段体动、呼吸/心脏候选波形及窗口速率图，红色区域表示扩展体动污染 |

逐帧字段：`motion_flag` 是阈值判定的体动，`artifact_flag` 包含前后保护段，`waveform_valid` 还考虑短片段和滤波端点。污染位置保留原始帧和体动指标，呼吸/心脏候选波形写 NaN，不能把 NaN 当零填充。`phase_rad` 在可处理片段内保留诊断用相位，其边界不一定具有有效呼吸/心率波形。

速率不强行扩展到每帧：一项速率对应其明确的 30 秒区间，`end_frame_exclusive` / `end_time_exclusive` 表示右端不包含。滑动窗口重叠，因此相邻速率记录不是独立观测。可按时间中心与情绪标注对齐，但不要用插值后的速率计算逐搏 HRV。

## 时间规则

`timestamp[i] = 目录开始时间 + i / 100 秒`，默认目录时间是中国标准时间 `Asia/Shanghai`（UTC+08:00）。例如首帧 `2026-11-05T19:36:34.000+08:00`，第 100 帧（索引 99）为 `19:36:34.990`，下一文件首帧索引 100 为 `19:36:35.000`。

10000 帧覆盖时长为 100 秒；首尾帧时间差为 99.99 秒。首文件编号允许从 0 或 1 开始，两者均视为目录起点；必须确认目录未被截取且首文件确为采集首文件。无硬件时间戳时无法识别文件内部丢帧、采集停顿、设备时钟漂移，也无法确认目录命名时刻与真正首帧的偏差。这些是推算时间，不能宣称硬件精确同步。

## HRV / 情绪分析

30 秒平均心率序列不是 NN 间期。`candidate_ibi.csv` 只是候选峰间期，不是已验证的 RR/NN。`interval_plausible=True` 仅表示处于允许心率范围，并不证明没有漏搏、重搏或呼吸谐波；不可直接作为可靠 HRV。应使用同步 ECG/PPG 验证峰时刻，完成逐搏质量、漏检/误检、异常搏动处理，再在连续有效片段计算 HRV。不要跨体动缺口连接间期。常见频域 HRV 通常需要更长的稳定记录（例如 5 分钟），30 秒窗口不适合直接解释完整频域指标。因此本项目不默认输出未经验证的 RMSSD/SDNN/LF/HF。

## 模块与验证

- `main.py`：唯一日常输入配置和运行入口。
- `config.py`：硬件、窗口、频段及质量参数。
- `io.py`：BIN 校验、解析、目录时间识别。
- `signals.py`：体动、片段、固定通道选择、连续波形。
- `physiology.py`：窗口速率、质量与候选逐搏间期。
- `pipeline.py`：协调、CSV/NPZ/JSON 和图像输出。
